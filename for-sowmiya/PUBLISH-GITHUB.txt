CURRENT PUBLISHING SETUP
GitHub Pages uses Deploy from a branch: gh-pages, / (root).
Push source changes to main. The workflow builds the static site, updates gh-pages,
and explicitly requests a Pages build. Do not change the source to GitHub Actions.
The built-in pages build and deployment job publishes the website.
This replaces the old direct deployment setup after a stuck Pages deployment.

HISTORICAL SETUP NOTES (publishing-source steps below are superseded):

PUBLISH USING GITHUB PAGES

1. Commit and push .github/workflows/pages.yml, the root .gitignore,
   for-sowmiya/build_pages.py, and for-sowmiya/pages-verification.json.
2. On GitHub open the repository, then Settings > Pages.
3. Under Build and deployment, select GitHub Actions as the Source.
4. Open Actions > Publish website to GitHub Pages > Run workflow > main.
5. After the job succeeds, Settings > Pages displays the website link.
   Later pushes to main that change the website deploy automatically.

GitHub Free supports Pages from public repositories. Pages from private
repositories requires an eligible paid plan. A private source repository
by itself does not make a standard Pages website private.

The original Python version still works locally with python server.py.
The build creates a separate _site directory using only selected files.
It never publishes .local-security.json, server.py, or browser previews.
Photos and videos referenced in story.json are copied into the public site.

The Pages birthday/movie form is only a browser-side interactive gate.
It does not protect media or story.json from direct access. The stored
answer digest avoids plaintext answers but is not secure authentication.
robots.txt requests no indexing; it does not enforce privacy.

The site needs HTTPS (provided by GitHub Pages) or localhost for the
browser answer check. Opening index.html directly as a file is unsupported.
No external hosting account or Python server is needed for visitors.

To build locally: python for-sowmiya/build_pages.py from repository root.
The output must not already exist, preventing accidental stale-file uploads.
The GitHub Actions build runs in a fresh checkout each time.
